## 🔴 CRITICAL

### C1 — Action button text contrast fails WCAG 1.4.3 (Minimum Contrast)

**Location:** `ActionButtonGroup.svelte` (`.action-btn.primary`, `.action-btn.danger`), `ImplementButton.svelte` (`.implement-btn`)

**Current state:**
| Button | Foreground | Background | Ratio | Required |
|--------|-----------|------------|-------|----------|
| Primary/Implement (`▶ Mehet`) | `#fff` | `#56d364` (green) | **1.93:1** | 4.5:1 |
| Danger/Error (`❌`) | `#fff` | `#ff7b72` (red) | **2.52:1** | 4.5:1 |
| Accent (`📋 Log`) | `#fff` | `#58a6ff` (blue) | **2.53:1** | 4.5:1 |

**WCAG criterion:** 1.4.3 Contrast (Minimum) — Level AA  
**Fix:** Use dark text on light backgrounds or darken button backgrounds.
- Primary button: use `color: #0d2b0d` (dark green text on green) or `background: #1a7f37`
- Danger button: use `color: #2d0000` (dark red text) or `background: #cf222e`
- Accent button: use `color: #0a1d3d` (dark blue text) or `background: #1f6feb`

**Files to change:**
- `src/lib/components/shared/ActionButtonGroup.svelte` (lines 286-299 in style)
- `src/lib/components/shared/ImplementButton.svelte` (lines 70-90 in style)

### C2 — `⚠ Stale` warning text hardcoded as emoji-only

**Location:** `src/lib/components/tabs/Overview.svelte:162`

```svelte
<div class="stale-warn">⚠ Stale</div>
```

The `⚠` has no `aria-label` or screen-reader accessible text. The visual yellow color (`var(--warn)`) alone may not be distinguishable for color-blind users.

**WCAG criteria:** 1.1.1 Non-text Content, 1.4.1 Use of Color  
**Fix:**
```svelte
<div class="stale-warn" role="alert">
  <span aria-hidden="true">⚠</span> Stale — {agent.lastRun}
</div>
```
Add explicit status text and expose through role.

### C3 — Status color dots are inaccessible as sole status indicators

**Location:** `Agents.svelte:102-105`, `Overview.svelte:154-158`

```svelte
<span class="status-dot {statusDotClass(agent.status)}"
      role="img" aria-label="Status: {agent.statusText}"></span>
```

Two issues:
1. `role="img"` with `aria-label` on an empty `<span>` is technically correct but fragile — some screen readers ignore `aria-label` on non-semantic elements without `role`.
2. The 8px dot provides no visible text. Color-blind users cannot distinguish `var(--green)` / `var(--yellow)` / `var(--red)`.

**WCAG criteria:** 1.1.1 Non-text Content, 1.4.1 Use of Color  
**Fix:** Add a text label visible to all users, or use CSS `::after` with the status word for screen readers:
```svelte
<span class="status-dot {statusDotClass(agent.status)}" aria-hidden="true"></span>
<span class="sr-only">{agent.statusText}</span>
```
Then in Agents table, render the status text column first so it's not redundant.

### C4 — Tab bar hidden scrollbar without focus indicator

**Location:** `src/lib/components/tabs/Overview.svelte` (in `+layout.svelte` style, lines 188-192)

```css
.tab-bar {
  overflow-x: auto;
  scrollbar-width: none;
}
.tab-bar::-webkit-scrollbar {
  display: none;
}
```

Keyboard users cannot see that tabs overflow or where they are in the scroll. On narrow viewports (≤768px), tabs may be completely invisible off-screen.

**WCAG criterion:** 2.4.7 Focus Visible, 1.4.10 Reflow  
**Fix:** Remove `scrollbar-width: none` and the `::-webkit-scrollbar` hide, or replace with a thin-but-visible scrollbar. Better: use a priority+ pattern or wrap to two lines on mobile instead of horizontal scroll.

## 🟠 HIGH

### H1 — No skip-to-content link

**Location:** `src/routes/+layout.svelte` (missing), `src/app.html` (no bypass block)

No skip navigation mechanism exists. Keyboard users must tab through 16+ tab buttons on every page load.

**WCAG criterion:** 2.4.1 Bypass Blocks — Level A  
**Fix:** Add to `+layout.svelte`:
```svelte
<a href="#main-content" class="skip-link">Skip to main content</a>
```
```css
.skip-link {
  position: absolute;
  top: -100%;
  left: 0;
  background: var(--accent);
  color: #fff;
  padding: 8px 16px;
  z-index: 9999;
}
.skip-link:focus {
  top: 0;
}
```
Then add `id="main-content"` to `<main class="dashboard-main">` in `+page.svelte`.

### H2 — `outline: none` on focused interactive elements

**Location:** `Agents.svelte:192`, `Overview.svelte:308`, `Noema.svelte:481`

```css
.agent-card.clickable:focus-visible {
  border-color: var(--accent);
  background: rgba(255, 255, 255, 0.03);
  outline: none;  /* ← removes browser default focus indicator */
}
```

While `focus-visible` is used (good!), the `outline: none` removes the browser's default focus ring. The border-color change is subtle on a dark background (barely visible for low-vision users).

**WCAG criterion:** 2.4.7 Focus Visible — Level AA  
**Fix:** Remove `outline: none` and instead use:
```css
outline: 2px solid var(--accent);
outline-offset: 2px;
```
The border-color change alone is insufficient as the sole focus indicator.

### H3 — `lang` attribute mismatch (HTML says `en`, content is Hungarian)

**Location:** `src/app.html:2` `<html lang="en">`

About 60% of visible text is Hungarian ("Fő navigáció", "Eszközök", "Fejlesztés Alatt", "Mehet", "Keresés", button labels). Screen readers use `lang` to select pronunciation rules.

**WCAG criterion:** 3.1.1 Language of Page — Level A  
**Fix:** Set `lang="hu"` on `<html>` and add `lang="en"` spans on English-only fragments, or decide on a primary language. Short-term: use `lang="hu"` since the UI is primarily Hungarian.

### H4 — `<h1>` duplicated between layout and page

**Location:** `+layout.svelte:112` `<h1>Noema 🧠</h1>` + `+page.svelte:165` `<h2 class="sr-only">Noema 🧠</h2>`

Having two Noema headings creates a confusing document outline. The sr-only h2 in the page is visually hidden but audible to screen readers, creating redundancy.

**WCAG criterion:** 1.3.1 Info and Relationships  
**Fix:** Remove the `sr-only` h2 from `+page.svelte`. The layout h1 handles the page title. If needed, replace it with a hidden `aria-label` on `<main>`.

### H5 — Tab navigation lacks `aria-controls` and `tablist` pattern

**Location:** `+layout.svelte:124-150` (tab bars)

Both tab bars use `<nav>` with `<button>` elements and `aria-current`, but do not implement the full WAI-ARIA tab pattern:
- Missing `role="tablist"` on parent
- Missing `role="tab"` on buttons
- Missing `aria-controls` linking each tab to its panel
- No keyboard arrow-key navigation between tabs

**WCAG criterion:** 4.1.2 Name, Role, Value — Level A  
**Fix:** Implement proper ARIA tab pattern:
```svelte
<div role="tablist" aria-label="Fő navigáció">
  <button role="tab" aria-selected={active} aria-controls="panel-overview">...</button>
</div>
<div role="tabpanel" id="panel-overview">...</div>
```
Or keep the `<nav>` approach but add `aria-controls` linking to the tab content area.

## 🟡 MEDIUM

### M1 — Interactive elements below 24×24px touch target (WCAG 2.5.5)

**Location:** Multiple components

| Element | Size | File |
|---------|------|------|
| Status dots | 8×8px | Agents, Overview |
| Close button (✕) | 32×32px ✅ | AgentDetailPanel |
| Compact toggle | 24-28px estimated | Noema, DevJobIndicator |

Status dots at 8px are decorative but also convey critical information. Action buttons have `padding: 1px 8px` making them very small vertically.

**WCAG criterion:** 2.5.5 Target Size (Enhanced) — Level AAA (advisory for AA)  
**Fix:** Increase action button padding to `padding: 6px 12px`, use `min-height: 24px` for all interactive controls.

### M2 — DevPackageRow compact mode traps keyboard users

**Location:** `DevPackageRow.svelte:104-105`

```svelte
tabindex={compact ? -1 : 0}
```

When compact mode is active, entire package rows are removed from the tab order. Keyboard users cannot expand or interact with them.

**WCAG criterion:** 2.1.1 Keyboard  
**Fix:** Always keep `tabindex="0"` but handle interaction differently in compact mode (e.g., click opens detail instead of toggling). Never remove interactive elements from tab order.

### M3 — Emoticons in `aria-label` cause verbosity

**Location:** Tab definitions in `+layout.svelte:18-33`

```ts
{ id: "overview", label: "🏠 Overview" },
{ id: "agents", label: "🤖 Agents" },
```

The emoticons are included in the visible label text, meaning screen readers vocalize them (e.g., "house building Overview" for 🏠). Some screen readers announce emoji descriptions which vary by platform.

**WCAG criterion:** 2.5.3 Label in Name, 4.1.2  
**Fix:** Separate visual emoji from semantic label:
```svelte
<button aria-label="Overview">
  <span aria-hidden="true">🏠</span> Overview
</button>
```

### M4 — No semantic `<main>` landmark in layout

**Location:** `+layout.svelte:111-168`

The layout uses `<div class="main-column">` instead of a semantic landmark. The `+page.svelte` has `<main class="dashboard-main">` inside a `<div class="page-with-panel">`, but screen readers rely on `<main>` at the layout level for landmark navigation.

**WCAG criterion:** 1.3.1 Info and Relationships  
**Fix:** Change `<div class="main-column">` to `<div class="main-column" role="region" aria-label="Main content">` or restructure to place `<main>` at layout level.

### M5 — Search input lacks clear button and submit behavior

**Location:** `Noema.svelte:206-216`

```svelte
<input type="search" class="search-input" placeholder="Keresés..."
       bind:value={searchQuery}
       onkeydown={(e) => { if (e.key === 'Escape') searchQuery = '' }} />
```

The `<input type="search">` is correct, but:
- No clear/× button when text is present (some browsers add one, not all)
- No `aria-label` on the label wrapper (uses `<span class="sr-only">Keresés</span>` — good!)
- Pressing Enter doesn't submit anything (formless)

**WCAG criterion:** 3.3.2 Labels or Instructions  
**Fix:** Add a clear button visible when `searchQuery.length > 0`. Wrap in `<form>` with `onsubmit|preventDefault` for Enter behavior.

### M6 — `aria-current="page"` applied to only one tab at a time is correct, but `activeTab` resets on non-existent tab

**Location:** `+layout.svelte:134`

```svelte
aria-current={activeTab === tab.id ? 'page' : undefined}
```

Correct implementation. However, if `activeTab` is set to a non-existent ID, it stays on that broken tab with no visual/aria feedback. The fallback in `+page.svelte` renders the placeholder, but the tab bar shows no active tab.

**WCAG criterion:** 4.1.2 Name, Role, Value  
**Fix:** Validate `activeTab` against known tab IDs in `$effect` and reset to "overview" if invalid.

---

### M7 — Agent detail panel focus trap has edge cases

**Location:** `AgentDetailPanel.svelte:40-57`

The focus trap logic is well-implemented (saves/restores focus, Escape closes, Tab wraps). Two edge cases:
1. When panel opens with only one focusable element, Tab does nothing useful
2. `onkeydown` handler is on the panel `<div>`, not the document — if focus somehow leaves the panel (e.g., assistive tech), Tab no longer wraps

**WCAG criterion:** 2.4.3 Focus Order  
**Fix:** Move keyboard listener to `document` when panel is open (and clean up on close). Ensure at minimum 2 focusable elements (close button + content).

## 🟢 LOW

### L1 — Dark-only color scheme with no light mode support

**Location:** `src/app.html:7` `<meta name="color-scheme" content="dark" />`

No `prefers-color-scheme` media query handling. The `color-scheme: dark` meta locks UI widgets (scrollbars, form controls) to dark rendering. Users who prefer light mode or high contrast have no alternative.

**WCAG criterion:** 1.4.8 Visual Presentation (advisory), 1.3.6 (AAA)  
**Fix:** Add CSS custom properties for light theme:
```css
@media (prefers-color-scheme: light) {
  :root {
    --bg: #ffffff;
    --card: #f6f8fa;
    --border: #d0d7de;
    --text: #1f2328;
    --muted: #656d76;
    /* keep accent colors */
  }
}
```
Set `<meta name="color-scheme" content="dark light" />`.

### L2 — Inconsistent `prefers-reduced-motion` coverage

**Location:** Various

| Has prefers-reduced-motion | Missing |
|---|---|
| `app.css` (global) ✅ | `DevJobIndicator.svelte` (pulse animation) |
| `Agents.svelte` (implicit via app.css) ✅ | `CronSidebar.svelte` (now-pulse animation) |
| `AgentDetailPanel.svelte` (transition) ✅ | `DevPackageRow.svelte` (pulse animation) |
| `ActionButtonGroup.svelte` (transform) ✅ | `Noema.svelte` (live-pulse, seg transition) |

**WCAG criterion:** 2.3.3 Animation from Interactions  
**Fix:** Move all `@keyframes` animations to a single CSS file, and gate them behind `@media (prefers-reduced-motion: no-preference)`. The global `app.css` rule handles `transition-duration` but not keyframes.

### L3 — `<table>` captions present but inconsistent

**Location:** `Agents.svelte:82`, `Crons.svelte:117`, `H1.svelte:76`

All three data tables have `<caption>` elements ✅. However, the captions are in English ("Agent Registry", "Cron Job Registry", "H1 Bug Bounty Programs") while surrounding UI is Hungarian. Screen readers announce captions before the table structure.

**WCAG criterion:** 1.3.1 (Info and Relationships) — passing, but inconsistent  
**Fix:** Translate captions to Hungarian or add `lang="en"` on the caption element.

### L4 — `:focus-visible` not polyfilled for older browsers

**Location:** Multiple components

`:focus-visible` is used correctly throughout, but Safari <15.4 and older browsers fall back to `:focus`, which would show focus rings on mouse clicks.

**WCAG criterion:** 2.4.7 Focus Visible  
**Fix:** Add a `:focus:not(:focus-visible)` fallback rule, or use `focus-visible` polyfill.

### L5 — Error page uses different CSS variables than the main app

**Location:** `+error.svelte:33-40`

```css
background: var(--bg-primary, #111);
color: var(--text-primary, #f0f0f0);
```

Uses `--bg-primary` / `--text-primary` while the app uses `--bg` / `--text`. The error page always renders with fallback `#111` / `#f0f0f0` because the main CSS variables don't match.

**WCAG criterion:** 1.4.3 Contrast (Minimum)  
**Fix:** Change to `var(--bg, #0d1117)` and `var(--text, #c9d1d9)`.

### L6 — `KeyboardEvent.keyCode` not used (good), but no `code` property checks

**Location:** `AgentDetailPanel.svelte:40`, `DevPackageRow.svelte:83`

```ts
if (e.key === "Enter" || e.key === " ") { ... }
if (e.key === "Escape") { ... }
```

This is correct ✅. However, `e.key === " "` (space) does not fire on keyup in some assistive technology configurations. Consider adding `e.key === "Spacebar"` for IE11/legacy Edge, though this is minor with modern browser support.
